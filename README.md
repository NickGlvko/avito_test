# Поиск кандидатов для объявлений услуг

Решение возвращает до 50 `item_id` для каждого поискового запроса. Отправленный на платформу файл — `answer_semantic_full_D.csv`; его Recall@50 составил **0,798793**. Финальный вариант — `D_full_unweighted`: широкий поиск и CatBoostRanker, обученный на полном пуле кандидатов. Позднее проверенные смеси моделей не дали подтверждённого улучшения, поэтому отправленный вариант сохранён. Подробные измерения: [полный D-пул](reports/semantic_full_D.md) и [финальное сравнение](reports/semantic_final.md).

## Данные и признаки

`train.parquet` содержит только положительные пары «запрос — выбранное объявление». Остальные объявления считаются **неразмеченными альтернативами**, а не достоверно неподходящими. Поисковый корпус берётся из `benchmark_items.parquet`; `benchmark_queries.parquet` содержит запросы, для которых строится ответ.

- **Текст:** `search_query`, `item_title_raw`, `item_infm_params_text` и `item_description_raw`. Заголовок обозначает услугу, параметры её уточняют, описание помогает найти услуги, отсутствующие в заголовке. Отдельные поля дают лексические оценки; их очищенное объединение служит входом E5.
- **Контекст:** локация, категория, доставка и текст фильтров запроса; локация и категория объявления. Совпадение локации полезно, но не является жёстким ограничением: пользователи выбирают и исполнителей из других локаций.
- **Свойства объявления:** рейтинг, число отзывов и цена вместе с признаками пропусков. Они помогают выбрать между объявлениями с похожим текстом.
- **Сигналы поиска:** исходные оценки по полям, позиции и присутствие в источниках, сила оценки относительно лидера, совпадения слов и фильтров, косинусная близость E5, её ранг и отставание от лучшего кандидата.
- **Обучающие взаимодействия:** история похожих запросов даёт кандидатов; статистики популярности и совместимости категорий используются поисковыми каналами. При локальной проверке их считают только по разрешённой обучающей части.

Все пять `search_*` полей также определяют полную группу запроса при оценке. `query_id` и `item_id` служат для связи и выдачи, а не признаками модели. Объявления с одинаковыми заголовками остаются разными объектами, если различаются `item_id`.

## Алгоритм

Пул кандидатов объединяет топ-500 BM25 и символьного TF-IDF с мягким усилением совпадающей локации, варианты этих каналов со статистиками взаимодействий и историю похожих запросов. К ним добавляется до 200 ближайших объявлений E5 из всего допустимого корпуса и до 200 — из локации запроса. Дубликаты удаляются по `item_id`; ограничения диагностического корпуса применяются **до** выбора лучших кандидатов.

Используется открытая предобученная [`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small), ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Модель не дообучалась: входы имеют префиксы `query:` и `passage:`, предел 256 токенов, выходные векторы размерности 384 нормализуются. Локальные ONNX Runtime и FAISS IndexFlatIP обеспечивают кодирование и точный поиск без внешнего API.

Из полного D-пула 50 объявлений выбирает **CatBoostRanker** с PairLogit: 240 деревьев, глубина 6, learning rate 0,06, единичный вес группы. Обучение использует всех найденных кандидатов, а не прежнюю выборку из 150 альтернатив. Модель получает текстовые и смысловые признаки; история остаётся источником кандидатов, но отдельный блок исторических признаков в финальный отбор не входит. При равной оценке порядок определяется исходной строкой `item_id`.

Использованные открытые библиотеки: NumPy, SciPy, Polars, scikit-learn, CatBoost, Sentence Transformers, ONNX Runtime, FAISS и uv. BM25 и объединение поисковых источников реализованы в проекте.

## Локальная проверка и ошибки

Метрика — **macro Recall@50**: доля найденных выбранных объявлений считается отдельно для каждой полной группы запроса, затем усредняется. Идентификатора поискового события в train нет; несколько событий с одинаковыми пятью признаками могут объединиться в одну группу. Повторные пары удаляются.

Разбиение по группам отделяет train, dev и диагностический test. Для 15 000 обучающих групп признаки истории и статистики сформированы в трёхчастной out-of-fold схеме: собственная положительная пара не участвует в расчёте своих сигналов. Группы без найденного положительного объявления исключаются только из PairLogit, но остаются в знаменателе оценки.

На dev использованы два приближённых сценария: **union** ищет по объединению объявлений train и benchmark со всеми дополнительными конкурентами; **benchmark + ответы запроса** добавляет к benchmark только отсутствующие ответы текущего запроса. Оба сценария сохраняют все известные ответы в знаменателе, но не являются точным прогнозом платформы. Измерялись также полнота пула, потери поиска и отбора, географические срезы. Выбор делался по dev с парным bootstrap по нормализованным текстам. Test просматривался после фиксации решения, но неоднократно, поэтому остаётся диагностическим.

| Проверка | Recall@50 |
| --- | ---: |
| Union/dev; полнота пула 0,9159 | 0,7838 |
| Union/test, диагностический | 0,7867 |
| Benchmark + ответы/dev | 0,8533 |
| Benchmark + ответы/test, диагностический | 0,8531 |
| Платформа | **0,798793** |

Анализ выявил разные формулировки одной услуги при слабом совпадении слов — добавлены E5-признаки и смысловые каналы. RRF терял хорошие объявления, поддержанные одним источником, поэтому финальную пятидесятку выбирает CatBoost. Выборка из 150 альтернатив покрывала лишь 27,3% неразмеченных кандидатов смыслового топ-50 внутри старого пула; обучение на полном пуле заметно улучшило отбор. Жёсткая география теряла исполнителей из других локаций: оставлены мягкий сигнал и глобальный E5-поиск. Квоты для других локаций и дополнительные глобальные текстовые каналы ухудшили общий Recall@50 и не вошли в решение. Узкая ранняя проверка переоценивала историю; расширенная проверка помогла отделить пользу её кандидатов от пользы исторических признаков. Ошибки на других локациях полностью не устранены.

## Воспроизведение отправленного CSV

Команды выполняются из корня проекта на Python 3.14. Зависимости устанавливаются в `.venv` через uv; новые пакеты при необходимости добавляются через `uv add`. В репозитории должны быть три исходных Parquet-файла, сохранённые веса, предыдущий контрольный `answer_semantic_full.csv` и **только необходимые для финального предсказания** файлы из `artifacts/`. Они явно разрешены в `.gitignore`; большие файлы отслеживаются через Git LFS по `.gitattributes` (около 3,9 ГиБ исходных данных и артефактов). Перед клонированием и загрузкой репозитория требуется установленный Git LFS. Полные временные обучающие таблицы и кэши в репозиторий не включаются. Подготовка артефактов из исходных данных описана в [подготовке E5](reports/semantic_setup.md), [обучении на полном B-пуле](reports/semantic_full_pool.md) и [обучении на полном D-пуле](reports/semantic_full_D.md).

```powershell
git lfs install
git lfs pull
uv --cache-dir .uv-cache sync --frozen
uv --cache-dir .uv-cache run --offline --frozen python -X utf8 -m avito_test.semantic_full_d_predict
uv --cache-dir .uv-cache run --offline --frozen python -X utf8 -m avito_test.semantic_full_d_verify
Get-FileHash answer_semantic_full_D.csv -Algorithm SHA256
```

Предсказание заново рассчитывает статистики взаимодействий по всему train, использует сохранённые веса и векторы и проверяет CSV. Проверка сверяет 2452 запроса, ровно 50 уникальных допустимых `item_id` для каждого, исходные данные, веса, соответствие строк векторам и контрольные суммы. Повторный офлайн-запуск должен дать SHA256 **`02070e34e69d763f8ebc2d1e78ccd757881c864c684b68cf8aad2eb148a2289c`**. В `models/semantic_full_D_v1/config.json` записаны версия E5, выбор модели, контрольные суммы и измеренное время предсказания.

Проверки кода: `uv --cache-dir .uv-cache run --offline --frozen python -X utf8 -m unittest discover -s tests -v`.
