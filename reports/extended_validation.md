# Расширенная валидация фиксированного CPU baseline

Проверка на платформе: **Recall@50 = 0.666981**. Ранее на узкой локальной test-выборке получено 0.7552. Ниже сравниваются условия проверки; параметры моделей и answer.csv не изменяются.

## Основные наблюдения (test)

- **benchmark_plus_positives**: Recall@50 0.7655, полнота объединения 0.9274. При отборе потеряно 7660 положительных ответов (16.4% всех ответов, 71.2% всех пропусков). Для ответов вне benchmark устойчивый выигрыш истории не подтверждён: Δ Recall@50 -0.0000, 95% интервал [-0.0022, +0.0020].
- **union**: Recall@50 0.6639, полнота объединения 0.8785. При отборе потеряно 10260 положительных ответов (21.9% всех ответов, 65.7% всех пропусков). Для ответов вне benchmark история ухудшает результат: Δ Recall@50 -0.0086, 95% интервал [-0.0105, -0.0068].
- Текстовый RRF с географией в union даёт Recall@50 0.6780; RRF со статистиками — 0.6718. В этой схеме популярность и история не улучшили отбор первых 50.
- На прежней узкой когорте при поиске в union потерь отбора 446 из 1875 ответов (23.8%); старое значение — 314 из 1875 (16.7%). Дополнительные конкуренты усиливают проблему даже на одних и тех же запросах.
- На этих же 1820 запросах при общем текстовом индексе Recall@50 падает с 0.7552 (benchmark + ответы) до 0.6361 (union). Это прямое сравнение влияния доступного корпуса при фиксированных словарях, IDF и обучающих взаимодействиях.

В исходном узком test потери отбора составляли 314 / 1875 = 16.7% всех положительных ответов и 314 / (314 + 135) = 69.9% пропусков. Сравнивать только абсолютные количества при разных размерах выборок нельзя.

Численная близость union и результата платформы сама по себе не подтверждает точность такой оценки: группы train могут отличаться от событий бенчмарка и по формулировкам, и по поведению пользователей.

## Протокол

- Сохранены исходные group_id и split с seed 20260926: train < 8, dev = 8, test = 9.
- Обучающие взаимодействия: 397,637. История, популярность и соответствия категорий построены только по этой части.
- Корпус union: **515,895** объявлений = 189,212 benchmark + 326,683 дополнительных train item_id. Все конкуренты участвуют в поиске; одинаковые заголовки не схлопываются.
- Корпус benchmark_plus_positives: весь benchmark плюс недостающие положительные объявления только текущего запроса. Объявления, добавленные для других запросов, недоступны.
- Маска корпуса применяется до топ-500 каждого источника и до поиска 20 соседних исторических текстов. Недоступные объявления не занимают места кандидатов.
- Словари, IDF, средние длины BM25 рассчитаны один раз по union; в обоих сценариях они одинаковы. TF-IDF истории также фиксирован и обучен только на train-взаимодействиях с объявлениями union. Переобучения словарей под каждый запрос нет.
- Это приближение отличается от полной перестройки индекса по benchmark + ответы для каждого запроса. Оно позволяет отделить влияние доступных конкурентов от смены IDF. Поэтому даже прежняя узкая когорта во второй схеме может отличаться от старого baseline.
- Параметры: прежние веса полей, множитель географии 16, RRF k=60, глубина 500, вес истории 0.5. Новые варианты не подбирались. Test уже просмотрен ранее и является диагностическим.
- Наличие добавляемого объявления известно из разметки только при формировании диагностического корпуса; эта метка не передаётся в score или обучающие статистики.

Оба сценария приближенные: union увеличивает конкуренцию и меняет состав корпуса; benchmark_plus_positives использует знание правильных ответов и не добавляет всех их естественных конкурентов. Ни одно число не является точным прогнозом платформы.
