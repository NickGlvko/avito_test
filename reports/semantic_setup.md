# Подготовка эксперимента с E5

Контрольным решением остаётся отправленный CatBoost (`answer_ranker.csv`, Recall@50 платформы 0.692247). Варианты A–D будут оценены на прежнем разбиении и двух схемах корпуса; до результатов dev выбор не сделан.

Используется локальная open-source модель [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small), ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Исходные веса и токенизатор лежат в `models/multilingual-e5-small-614241f6`, точный экспорт ONNX — в `models/multilingual-e5-small-614241f6-onnx`. Запуск модели и дальнейшее воспроизведение выполняются без сети. Запрос кодируется как `query: ` + очищенный `search_query`; объявление — как `passage: ` + заголовок, параметры, описание. Очистка удаляет HTML и повторные пробелы, сохраняя регистр и пунктуацию. Общий предел 256 токенов; заголовок и параметры идут перед описанием. Векторы L2-нормированы, размерность 384.

## Проверка backend на CPU

Измерение кодирования на фиксированных 2400 объявлениях: по 800 с коротким (<500 символов), средним (500–1999) и длинным (≥2000) описанием. Машина: Windows, Python 3.14, 12 логических CPU и 31.7 GiB RAM. Скорость поиска будет измерена отдельно.

| Backend | Секунд | Объявлений/с | Оценка для 515895 объявлений |
| --- | ---: | ---: | ---: |
| PyTorch float32 | 149.2 | 16.1 | 8.9 ч |
| ONNX Runtime float32 | 136.7 | 17.6 | 8.2 ч |
| ONNX Runtime int8 | 88.2 | 27.2 | 5.3 ч |

В отдельной проверке на 192 входах float32 ONNX практически совпал с исходной моделью: минимальная косинусная близость соответствующих векторов 0.99999988, пересечение топ-20 для 64 запросов среди 128 объявлений — 100%. У int8 средняя близость 0.985, пересечение топ-20 — 78.8%; поэтому для основного сравнения A–D оставлен точный float32.

Прямой OpenVINO CPU-движок на той же ONNX-модели дал совпадающие векторы, но в коротком замере при работающем параллельно кодировании оказался медленнее. Этот замер выполнялся под конкурирующей нагрузкой и не является универсальным сравнением backend.

Фактическая скорость полного корпуса ниже экстраполяции короткой пробы: тексты отсортированы по длине для уменьшения padding, и большая часть оставшихся описаний достигает предела 256 токенов. Векторы сохраняются с контрольными точками. Для 515895 объявлений обнаружено 515836 уникальных входных текстов; отображение каждого `item_id` на строку векторов сохраняется отдельно.

Дополнительно проверена обработка непересекающихся диапазонов тремя и двумя процессами. На длинных текстах суммарная скорость оказалась ниже, чем у одного процесса ONNX Runtime с восемью потоками; расчет возвращён к одному процессу с возобновлением каждого диапазона с его контрольной точки. Для принятия решения об ускорении использовалась фактическая скорость полного корпуса, а не только короткий бенчмарк.

## Контроль обучения

Повторно обученный A использует те же 407222 OOF-строки, 2691 группы и 3572 положительные строки. Его предсказания на первых 20000 сохранённых строк совпали со старой моделью точно; файлы CatBoost побайтно различаются. Полный replay трёх частей подтвердил точное совпадение всех исходных признаков, меток, порядка групп и выборки кандидатов. Значит, B получит только три новых E5-признака на тех же самых обучающих парах.

Для C/D подготовлен отдельный OOF-проход по тем же 3000 запросам. Положительные объявления попадают в обучающую таблицу только если найдены общим пулом; остальные ограничены 150 конкурентами на запрос. История и статистики строятся по двум другим частям train. Допустимый корпус в диагностической схеме «benchmark + ответы» применяется до выбора семантических топ-200.

После завершения кодирования команды запуска и результаты будут добавлены в `reports/semantic.md` и README.
